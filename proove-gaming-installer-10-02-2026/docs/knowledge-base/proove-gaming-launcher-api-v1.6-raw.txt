Перевіряє доступність email та валідність пароля перед реєстрацією.
Якщо валідація успішна, API автоматично генерує варіанти нікнеймів.
Ендпоінт
POST api/check_email
Автентифікація
Не потрібна.
Запит
{
"email": "player@example.com",
"password": "TestPass123"
}

"PlayerX",

"PlayerPlay"

"message": "Email required"
}

}

"success": false,

Генерація нікнеймів
Після успішної валідації email API автоматично генерує до п'яти доступних варіантів нікнеймів.
Правила генерації:
За основу береться локальна частина email-адреси.
Видаляються непідтримувані символи.
Перед поверненням варіантів перевіряється унікальність.
У разі конфлікту автоматично генерується інший нікнейм.
Максимальна довжина нікнейма — 20 символів.
Використовується той самий механізм генерації нікнеймів, що й в усіх пов'язаних ендпоінтах.
2. Check Nickname (перевірка нікнейма)
Перевіряє доступність нікнейма.
Ендпоінт
POST api/check_nickname
Автентифікація
Не потрібна.
Запит
{
"nickname":"PlayerNova"
}
Успішно
HTTP 200
{
"success": true,
"message": "Nickname is available",
"nickname": "PlayerNova"
}
Нікнейм вже існує
HTTP 409
{
"success": false,
"errors": [
{
"error_code": "NICKNAME_ALREADY_EXISTS",
"field": "nickname",
"message": "Nickname already exists"
}
],
"suggestions": [
"PlayerNova25",
"PlayerPro",
"PlayerGG",
"PlayerPlay",
"PlayerX"
]
}
Правила валідації
Мінімальна довжина: 3 символи.
Максимальна довжина: 20 символів.
Лише латинські літери.
Цифри дозволені.
Знак підкреслення (_) дозволений.
Пробіли не дозволені.
Нікнейм має бути унікальним.
Варіанти нікнеймів
Якщо запитаний нікнейм вже існує, API автоматично генерує до п'яти альтернативних нікнеймів.
Усі згенеровані нікнейми:
унікальні;
відповідають правилам валідації;
одразу доступні для реєстрації.

валідує підтвердження видалення;
видаляє аватар клієнта (якщо існує);
видаляє всі активні Session Token;
безповоротно видаляє обліковий запис клієнта.
Після видалення:
Вхід більше неможливий.
Усі Session Token стають недійсними.
Обліковий запис неможливо відновити.

"message": "Password required"
}
Невірний пароль
HTTP 401
{
"success": false,

Ендпоінт
POST api/forgotten
Автентифікація
Не потрібна.
Запит
{
"email":"user@example.com"
}
Успішно
HTTP 200
{
"success":true,
"message":"Password reset email sent"
}
Процес відновлення пароля
API автоматично:
валідує email;
генерує Reset Code;
зберігає Reset Code;
зберігає час закінчення дії;
надсилає лист для скидання пароля.
Термін дії Reset Code:
15 хвилин
Сторінка скидання пароля
https://proovegaming.com/index.php?route=account/reset_password&code=RESET_CODE
Помилка валідації
HTTP 400

"message":"Invalid email"
}
Email не знайдено
HTTP 404
{

"error_code":"EMAIL_NOT_FOUND",
"field":"email",
"message":"Email not found"
}
Помилка надсилання пошти
HTTP 500
{
"success":false,
"error_code":"MAIL_ERROR",
"message":"Mail error"
}

EMAIL_REQUIRED
INVALID_EMAIL

15. Reset Password (скидання пароля)
Змінює пароль за допомогою Reset Code.
Ендпоінт
POST api/reset_password
Автентифікація
Не потрібна.
Запит
{
"code":"RESET_CODE",
"new_password":"NewPass123"
}
Успішно
HTTP 200
{
"success":true,
"message":"Password has been reset successfully",
"customer":{
"customer_id":15,
"email":"user@example.com"
}
}
Процес скидання пароля
Після успішної зміни пароля API:
оновлює пароль клієнта;
видаляє Reset Code;
видаляє час закінчення дії Reset Code;
видаляє всі активні Session Token.
Клієнт має увійти повторно.
Недійсний Reset Code
HTTP 400
{
"success":false,
"error_code":"INVALID_OR_EXPIRED_RESET_CODE",
"message":"Invalid or expired reset code"
}
Можливі коди помилок
RESET_CODE_REQUIRED
PASSWORD_REQUIRED
PASSWORD_TOO_SHORT
PASSWORD_NO_UPPERCASE
PASSWORD_NO_NUMBER
PASSWORD_HAS_SPACES
INVALID_OR_EXPIRED_RESET_CODE

Безпека паролів

усі Session Token видаляються;
клієнт має увійти повторно.
