1. Check Email
Checks email availability and password validity before registration.
If validation succeeds, the API automatically generates nickname suggestions.

Endpoint
POST api/check_email

Authentication
Not required.

Request
{
"email": "player@example.com",
"password": "TestPass123"
}

Success Response
HTTP 200
{
"success": true,
"message": "Email and password are valid",
"nicknames": [
    "PlayerNova",
    "PlayerPro",
    "PlayerX",
    "PlayerGG",
    "PlayerPlay"
]
}

Nickname Generation
After successful email validation the API automatically generates up to five available nickname suggestions.
Generation rules:
●   Uses the local part of the email address as the base.
●       Removes unsupported characters.
●   Checks uniqueness before returning suggestions.
●   Automatically generates another nickname if a conflict occurs.
●   Maximum nickname length is 20 characters.
●   Uses the same nickname generation engine as all nickname-related endpoints.

2. Check Nickname
Checks nickname availability.

Endpoint
POST api/check_nickname

Authentication
Not required.

Request
{
    "nickname":"PlayerNova"
}

Success
HTTP 200
{
"success": true,
"message": "Nickname is available",
"nickname": "PlayerNova"
}

Nickname already exists
HTTP 409
{
"success": false,
"errors": [
    {
        "error_code": "NICKNAME_ALREADY_EXISTS",
        "field": "nickname",
        "message": "Nickname already exists"
    }
],
"suggestions": [
    "PlayerNova25",
    "PlayerPro",
    "PlayerGG",
    "PlayerPlay",
    "PlayerX"
]
}

Validation Rules
●       Minimum length: 3 characters.
●       Maximum length: 20 characters.
●       Latin letters only.
●       Numbers allowed.
●       Underscore (_) allowed.
●       Spaces are not allowed.
●       Nickname must be unique.

Nickname Suggestions
If the requested nickname already exists, the API automatically generates up to five alternative nicknames.
All generated nicknames:
●       are unique;
●       satisfy validation rules;
●   are immediately available for registration.

11. Password Change Link
Returns a secure web link for changing the customer's password.
Unlike
api/forgotten
the customer does not enter an email address.
The customer is identified using the current Session Token.

Endpoint
POST api/profile/password_link

Authentication
Bearer Token required.

Headers
Authorization: Bearer USER_SESSION_TOKEN
Content-Type: application/json

Request
{}

Success
HTTP 200
{
"success": true,
"password_change_url": "https://proovegaming.com/index.php?route=account/reset_password&code=RESET_CODE",
"expires_in_minutes": 15
}

Launcher

↓

User clicks Change Password

↓

Launcher displays an email input dialog

↓

User enters the account email

↓

Launcher calls POST /api/forgotten

↓

API sends a password reset email

↓

Customer opens the reset link from the email

↓

Customer sets a new password on the website

↓

All Session Tokens become invalid

↓

On the next authorized API request Launcher receives
INVALID_OR_EXPIRED_TOKEN

↓

Launcher asks the customer to sign in again

Account Deletion Process
After successful validation the API automatically:
●       validates Session Token;
●       validates customer password;
●       validates deletion confirmation;
●   deletes customer avatar (if exists);
●   removes all active Session Tokens;
●   permanently deletes the customer account.
After deletion:
●   Login is no longer possible.
●   All Session Tokens become invalid.
●   The account cannot be restored.

●       POST api/check_email
