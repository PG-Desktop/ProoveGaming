# BLAZE / X43 — LED 无法点亮：复位为默认的数据与结果（提供给工厂 / 固件团队）

> 说明：本文件是给厂商的**外发沟通**中文版本，是 English 报告 `blaze-led-vendor-report-2026-07-28.md`
> 的翻译。仓库文档规范为英文；此中文件为发送给工厂而特意保留的例外。

这是给工厂 / 固件团队的具体报告。它展示了我们将设备复位为默认 profile 时**确切发送的数据**（按照
27.07 问答所述，写入 `0x02` 与 `0x03` 两个 table），以及**实际现象**：按键、DPI、回报率以及整个
profile 都正常工作，但 **LED 始终无法点亮**——无论通过软件，还是通过底部的灯效切换实体开关。

## 结果摘要

| 功能 | 结果 |
|---|---|
| 左键 / 右键 / 中键 / 前进 / 后退 | ✅ 正常 |
| DPI 档位切换（DPI 按键） | ✅ 正常 |
| 回报率切换（回报率按键） | ✅ 正常 |
| 写入 flash 的 7 个 DPI 档位 | ✅ 已应用 |
| **LED（任意灯效）** | ❌ **始终不亮** |

因此 profile 写入本身是正确的，并且**已写入 flash**——除 LED 外一切都有响应。LED 在**任何**
effect 值、亮度、颜色槽或速度下都不亮，并且**按下底部灯效切换开关时也不亮**。

## 设备

- BLAZE / X43，USB **VID `0x04D9` / PID `0xA245`**（有线连接）。
- 采用 Easen param 协议：8 字节 header 通过 HID SET_REPORT（feature）发送，随后 64 字节数据块
  通过中断输出端点 `0x03` 发送。校验和字节会发送，但按 Easen 规格，固件并不校验它。

## 我们复位为默认时确切发送的数据

以下为完整的默认 profile 写入。所有数值复现 OEM 抓包。字节为十六进制。

### 1) `0x03` — SetParameter_1（三个 64 字节 block，一起写入）

Header（`[cmd, profile, index, 0, 0, status=0x07（全部 block）, times=3, cs]`）:
```
03 00 00 00 00 07 03 00
```

**Block 0 — DPI 表与 sensor 配置**（debounce/scale = 0，`dpiStage_Max = 7`，档位
200/800/1600/3200/6400/9600/12000）:
```
00 00 00 00 07 00 00 00 00 C8 00 20 03 40 06 80
0C 00 19 80 25 E0 2E 00 00 C8 00 20 03 40 06 80
0C 00 19 80 25 E0 2E 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

**Block 1 — 颜色**（DPI 指示 RGB 全为 0；LED 槽 = 红、蓝、绿、黄、青、品红、橙、白）:
```
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 FF 00 00 00 00 FF 00 FF
00 FF FF 00 00 FF FF FF 00 FF FF 80 00 FF FF FF
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

**Block 2 — 按键矩阵**（16 个条目 × `[code, b1, b2, mode]`）:
```
F0 00 00 02  F1 00 00 02  F2 00 00 02  F4 00 00 02
F3 00 00 02  03 00 00 0B  03 00 00 06  03 00 00 0A
00 00 00 02  00 00 00 02  00 00 00 02  00 00 00 02
00 00 00 02  00 00 00 02  00 01 00 04  00 02 00 04
```

### 2) `0x02` — SetParameter_0（一个 64 字节 block）

Header（`[cmd, profile, index, 0, 0, status=0, times=1, cs]`）:
```
02 00 00 00 00 00 01 00
```

数据（`[0]` reportrate=1000 Hz，`[1]` dpi_stage=0，`[2]` ledEffect，`[3]` 亮度=255，
`[4]` 速度=3，`[5]` 颜色槽=0，`[6]` option=0）:
```
01 00 02 FF 03 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

写入之后我们还发送了 `0x01`（选择/激活 profile 0）——LED 仍无变化。

## 针对 LED 我们尝试的变化——均无法点亮 LED

`0x02` 的字节 `[2]`（ledEffect）在规格列出的每个值上都尝试过，亮度为 `0xFF`：

| ledEffect | 名称（按规格） | 结果 |
|---|---|---|
| `0x00` | 关闭 | LED 关闭（符合预期） |
| `0x02` | 呼吸 | **不亮** |
| `0x03` | 霓虹 | **不亮** |
| `0x06` | 雨滴 | **不亮** |

此外，以下变化对 LED 也无任何影响：亮度 `0x00`–`0xFF`、速度 `0x01`–`0x07`、颜色槽 `0`–`7`
（含 `7` = 循环）、option `0`/`1`，以及在写 effect 之前先写颜色表（block 1）。任何组合下 LED 都不亮。

## 写入确实到达并写入 flash 的证据

- 将 block 2 中 **DPI 按键槽（KEY5）留空**，会使 **DPI 按键失效**；再写回 `03 00 00 0B` 则恢复。
  因此 block 2 的写入确实被固件接收并保存。
- 按键、DPI 切换、回报率切换的行为都与上面的按键矩阵完全一致。只有 LED 无响应。

## 底部灯效切换实体开关同样无法点亮 LED

根据 27.07 的回复，底部按键为回报率切换和**灯效切换**。在按键矩阵的 LED 槽（KEY7）保持其原生绑定的
情况下，按下底部灯效切换开关**同样无法点亮 LED**——这是一个完全不经过我们软件的实体控制。

## 给厂商的问题

1. 在已写入默认 profile 并选择任意灯效的情况下，LED 始终不亮——**是什么使能 LED 引擎？** 是否有
   我们写入时遗漏的 LED 使能字节/步骤（例如在 param_0、block 1 的保留字节，或单独的命令中）？
2. 底部的**灯效切换实体开关**也无法点亮 LED。这是否表示该样机存在**硬件/固件故障**，还是该开关依赖
   某个前置状态？
3. 是否存在某个必须先运行的产测/工厂步骤（或 LED 自检命令），LED 才能工作？如有，能否提供确切的字节
   序列？
4. 能否确认固件期望的、能点亮 LED 的**默认 param_0**（report rate、dpi_stage、ledEffect、亮度、
   速度、颜色、option）的确切字节示例？
